# Claude Code Workflow Template

A structured template for building applications with Claude Code using the **PIV Loop** workflow — Prime → Implement → Validate.

Clone this repo as the starting point for any new project. It provides slash commands, reference documentation, skills, and best practices for AI-assisted development.

> **`myworkshop` branch** — personalised for Charles Vosloo / CogStack. Wired into `~/.claude/` via symlinks so commands are available globally across all projects.

---

## Global Installation (CogStack Setup)

This branch is designed to be cloned once and symlinked into `~/.claude/` so all commands, rules, and reference docs are available in every Claude Code session — not just per-project.

```bash
# 1. Clone to your home directory
git clone -b myworkshop https://github.com/journeyman33/claude-code-template ~/claude-code-template
cd ~/claude-code-template

# 2. Symlink into ~/.claude/ (preserves settings.json, sessions, history)
mkdir -p ~/.claude
ln -sfn ~/claude-code-template/.claude/commands  ~/.claude/commands
ln -sfn ~/claude-code-template/.claude/rules     ~/.claude/rules
ln -sfn ~/claude-code-template/.claude/reference ~/.claude/reference
ln -sfn ~/claude-code-template/.claude/skills    ~/.claude/skills

# 3. Populate CLAUDE.md with your project/machine context (see below)
# Then symlink it into any working directory you run claude from:
ln -sfn ~/claude-code-template/CLAUDE.md ~/.hermes/CLAUDE.md  # example

# 4. Verify symlinks
ls -la ~/.claude/ | grep '\->'
```

> **Note:** `~/.claude/` holds Claude Code's runtime state (sessions, history, MCP cache, settings). Only the four subdirectories above are symlinked — everything else stays native.

## CLAUDE.md — Your Global Context File

`CLAUDE.md` in the repo root is your machine/identity context. Claude Code reads it automatically when you run `claude` from any directory that has it (or is symlinked to it).

Populate it once with your stack, active projects, and conventions. Use the template as a starting point:

```bash
cp .claude/CLAUDE-template.md CLAUDE.md
# Edit CLAUDE.md, then commit
git add CLAUDE.md && git commit -m "feat: populate CLAUDE.md for this machine"
```

Example content for a CogStack / self-hosted setup:

```markdown
# CogStack — Claude Code Context

## Who I Am
Charles Vosloo, founder/CEO of CogStack, AI infrastructure consultancy, Johannesburg SA.

## Stack
- Python: uv exclusively (never bare pip)
- TypeScript, Postgres, Docker Compose
- Shell: zsh + tmux | Editor: Zed in vim mode
- Commits: conventional commits

## Active Projects
- CTIS: tender.cogstack.co.za — Next.js + FastAPI
- cogstack-leadgen: n8n + Notion CRM + Python scraper
- Hermes: ~/.hermes/ — v0.7.0, Telegram @CogHermes_bot

## Do Not
- Never pip install outside a project venv
- Never commit .env files
- Never operate git on /mnt/d/ paths (cold archive, 9P filesystem)
```

## The PIV Loop

```
┌─────────┐     ┌─────────────┐     ┌──────────┐
│  PRIME  │ ──► │  IMPLEMENT  │ ──► │ VALIDATE │
└─────────┘     └─────────────┘     └──────────┘
     │                                    │
     └────────────────────────────────────┘
                    (iterate)
```

| Phase | Commands | What Happens |
|-------|----------|--------------|
| **Prime** | `/prime` | Claude reads CLAUDE.md, PRD, and codebase structure |
| **Implement** | `/plan-feature`, `/execute` | Plan written to `.agents/plans/`, then executed |
| **Validate** | `/validation:validate`, `/validation:code-review` | Lint, test, review |

## Step-by-Step Workflow

### 1. Start a session

```bash
cd /your/project   # or ~/.hermes for Hermes work
claude
```

### 2. Prime Claude

```
/prime
```

Loads CLAUDE.md, PRD.md, and codebase structure into context. Run at the start of every session.

### 3. Plan a feature (or pass a spec doc directly)

```
/plan-feature Add user authentication
```

Or pass an existing spec/troubleshooting doc:

```
/plan-feature /home/charles/.hermes/docs/HermesV0.7setup.md
```

Claude writes a detailed plan to `.agents/plans/<feature-name>.md`.

### 4. Execute the plan

```
/execute .agents/plans/add-user-authentication.md
```

Claude works through every task, runs validation commands after each step, and reports what was created or modified.

### 5. Validate

```
/validation:validate
/validation:code-review
```

Fix issues:

```
/validation:code-review-fix
```

### 6. Commit

```
/commit
```

### 7. Repeat from step 3

## Key Principles

- **Define before building** — a vague PRD produces vague code
- **Plan before executing** — the plan is the context that makes one-pass implementation possible
- **Validate frequently** — don't let failures accumulate
- **Keep CLAUDE.md current** — it is Claude's memory across sessions
- **Symlink, don't copy** — one repo, available everywhere

## Step-by-Step Workflow

### 1. Define your project

Open Claude Code and describe what you want to build.

```bash
claude
```

### 2. Create a PRD

```
/create-prd
```

Claude interviews you and writes `.claude/PRD.md` — your project blueprint covering features, user stories, tech stack, and API design.

### 3. Set up CLAUDE.md

Either fill in `.claude/CLAUDE-template.md` manually, or let Claude generate it:

```
/create-rules
```

This analyses the codebase and writes a `CLAUDE.md` tailored to your project.

### 4. Prime Claude

```
/prime
```

Loads CLAUDE.md, PRD.md, and codebase structure into context. Run this at the start of every session.

### 5. Plan a feature

```
/plan-feature Add user authentication
```

Claude analyses the codebase, researches patterns, and writes a detailed plan to `.agents/plans/add-user-authentication.md`.

### 6. Execute the plan

```
/execute .agents/plans/add-user-authentication.md
```

Claude works through every task in the plan, runs validation commands after each step, and reports what was created or modified.

### 7. Validate

```
/validation:validate
/validation:code-review
```

Fix any issues:

```
/validation:code-review-fix
```

### 8. Commit

```
/commit
```

### 9. Repeat from step 5

## Customising for Your Stack

### Different tech stack

Replace or add files in `.claude/reference/`. Reference them in CLAUDE.md under an "On-Demand Context" table so Claude knows when to read them.

### Different branching strategy

Edit `.claude/commands/commit.md` to match your workflow (GitFlow, trunk-based, etc.).

### Different test runner

Update `.claude/commands/validation/validate.md` to call your test commands.
