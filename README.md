# Claude Code Workflow Template

A structured template for building applications with Claude Code using the **PIV Loop** workflow — Prime → Implement → Validate.

Clone this repo as the starting point for any new project. It provides slash commands, reference documentation, skills, and best practices for AI-assisted development.

## Quick Start

### New Project from This Template

```bash
# 1. Use as GitHub template (recommended) or clone manually
git clone https://github.com/YOUR_USERNAME/claude-code-workflow.git my-new-project
cd my-new-project

# 2. If cloned (not templated), reset git history
rm -rf .git
git init
git add .
git commit -m "feat: initial project from claude-code-workflow template"

# 3. Push to your own GitHub repo
gh repo create my-new-project --public --source=. --push

# 4. Start Claude Code
claude
```

### Adding This Workflow to an Existing Project

```bash
# Clone just the .claude and .agents directories into your project
git clone --depth 1 https://github.com/YOUR_USERNAME/claude-code-workflow.git /tmp/claude-template
cp -r /tmp/claude-template/.claude /path/to/your/project/
cp -r /tmp/claude-template/.agents /path/to/your/project/
cp /tmp/claude-template/.claude/CLAUDE-template.md /path/to/your/project/CLAUDE.md
rm -rf /tmp/claude-template

# Customise CLAUDE.md for your project, then commit
git add .claude/ .agents/ CLAUDE.md
git commit -m "feat: add Claude Code workflow"
```

## The PIV Loop

```
┌─────────┐     ┌─────────────┐     ┌──────────┐
│  PRIME  │ ──► │  IMPLEMENT  │ ──► │ VALIDATE │
└─────────┘     └─────────────┘     └──────────┘
     │                                    │
     └────────────────────────────────────┘
                    (iterate)
```

| Phase | Commands | What Happens |
|-------|----------|--------------|
| **Prime** | `/prime` | Claude reads CLAUDE.md, PRD, and codebase structure |
| **Implement** | `/plan-feature`, `/execute` | Plan is written to `.agents/plans/`, then executed |
| **Validate** | `/validation:validate`, `/validation:code-review` | Lint, test, review |

## Step-by-Step Workflow

### 1. Define your project

Open Claude Code and describe what you want to build.

```bash
claude
```

### 2. Create a PRD

```
/create-prd
```

Claude interviews you and writes `.claude/PRD.md` — your project blueprint covering features, user stories, tech stack, and API design.

### 3. Set up CLAUDE.md

Either fill in `.claude/CLAUDE-template.md` manually, or let Claude generate it:

```
/create-rules
```

This analyses the codebase and writes a `CLAUDE.md` tailored to your project.

### 4. Prime Claude

```
/prime
```

Loads CLAUDE.md, PRD.md, and codebase structure into context. Run this at the start of every session.

### 5. Plan a feature

```
/plan-feature Add user authentication
```

Claude analyses the codebase, researches patterns, and writes a detailed plan to `.agents/plans/add-user-authentication.md`.

### 6. Execute the plan

```
/execute .agents/plans/add-user-authentication.md
```

Claude works through every task in the plan, runs validation commands after each step, and reports what was created or modified.

### 7. Validate

```
/validation:validate
/validation:code-review
```

Fix any issues:

```
/validation:code-review-fix
```

### 8. Commit

```
/commit
```

### 9. Repeat from step 5

## Command Reference

### Core PIV Loop

| Command | Description |
|---------|-------------|
| `/prime` | Load project context |
| `/plan-feature [description]` | Create implementation plan |
| `/execute [path-to-plan]` | Execute a plan |

### Validation

| Command | Description |
|---------|-------------|
| `/validation:validate` | Full validation suite |
| `/validation:code-review` | Technical review of changed files |
| `/validation:code-review-fix` | Fix issues found in review |
| `/validation:execution-report` | Post-implementation report |
| `/validation:system-review` | Implementation vs plan analysis |

### Bug Fixing

| Command | Description |
|---------|-------------|
| `/github_bug_fix:rca` | Root cause analysis for a GitHub issue |
| `/github_bug_fix:implement-fix` | Implement fix from RCA |

### Utilities

| Command | Description |
|---------|-------------|
| `/commit` | Atomic commit with conventional format |
| `/create-prd` | Generate PRD from conversation |
| `/create-rules` | Auto-generate CLAUDE.md |

### Skills

Skills are reusable workflows invoked from inside other commands or directly.

| Skill | Description |
|-------|-------------|
| `agent-browser` | Playwright-based browser automation CLI |
| `e2e-test` | Full E2E test workflow with browser + DB validation |

## Customising for Your Stack

### Different tech stack

Replace or add files in `.claude/reference/`. Reference them in CLAUDE.md under an "On-Demand Context" table so Claude knows when to read them.

### Different branching strategy

Edit `.claude/commands/commit.md` to match your workflow (GitFlow, trunk-based, etc.).

### Different test runner

Update `.claude/commands/validation/validate.md` to call your test commands.

## Key Principles

- **Define before building** — a vague PRD produces vague code
- **Plan before executing** — the plan is the context that makes one-pass implementation possible
- **Validate frequently** — don't let failures accumulate
- **Keep CLAUDE.md current** — it is Claude's memory across sessions
